# 05 - Open issues and dispositions

Single list of the bugs, inconsistencies, risks and product questions found in the Recorder 1.0 code and its dependencies (`COMP/`, `CRYPTO/`, the ansible image). It merges the four draft lists written with files 01-04, plus section J from the specification review; the draft IDs (`A` = 01, `B` = 02, `C` = 03, `D` = 04) are kept in the "Formerly" column so older notes still resolve. Duplicates found by several drafts are merged into one item. Citation prefixes: see the [README](README.md#source-baseline-and-citation-prefixes).

Each item has an anchor `#oi-nn`; files 01-04 link to it.

## Dispositions

Each item has one disposition. It tells a reimplementer what to do.

| Disposition | Meaning for a reimplementation |
|---|---|
| **keep** | Wire or disk compatibility depends on it, or the behaviour is acceptable. Reproduce it, even if it looks odd. |
| **fix** | A bug. Do not reproduce it. The "Recommendation" column gives the intended behaviour; it never changes what goes on the wire or on disk unless it says so. |
| **decide** | A product or security choice. The 1.0 behaviour is given; the product owner must confirm or change it. Until then, the recommendation applies. |
| **decided (x)** | A *decide* item the product owner has settled; (x) is the chosen option, and it is binding for the reimplementation. |
| **info** | Hygiene, build detail or a documented property. No direct effect on a reimplementation. |

Severity: **high** (data loss, security, or a feature that cannot work), **medium** (wrong behaviour a user will hit), **low** (cosmetic or rare).
